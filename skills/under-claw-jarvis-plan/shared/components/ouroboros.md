# Ouroboros 구성 모듈

출처: https://github.com/Q00/ouroboros (MIT). 원본을 재서술한 선택 방법론이다.
명세·검증의 실제 공통 계약은 [contract](../contract.md), [verification](../verification.md).

- 실행 전에 목적·범위·검증 기준을 명세로 고정한다. 모호성 숫자만으로 준비 완료를
  판단하지 않고, 실행을 바꾸는 미결정 질문이 남았는지 확인한다.
- 검사 비용이 작은 기계적 검증부터 수행하고 의미 검수와 독립 판정을 잇는다.
- 회차마다 명세 버전·산출물·검증 결과·미해결 기준·다음 시작 단계를 남겨 재개한다.
- 예산/회차/시간 한도가 있으면 시작 전에 기록하고 회차 사이에 확인한다.
  토큰·비용을 호스트가 제공하지 않으면 추정치를 실측으로 표현하지 않는다.
- 모델의 자기 점수, 명세 유사도, 합의 여부만으로 실제 성공을 선언하지 않는다.
- 현재 실행자는 under-claw다. 내부에서 `ooo run/ralph/evolve`를 추가로 돌리지 않는다.
  사용자가 Ouroboros 실행 엔진으로 전환하라고 지시하면 현재 루프를 종료하고 명세와
  증거를 인계한다. Work Tasks가 연결된 경우 그 원장을 중복 구현하지 않는다.
