# 00 · 루프 제어 — 명세·증거·필요 단계 재수행

첫 회차는 베이스 `under-claw-jarvis-plan`의 이해→계획→구현→검수 전체를 수행한다.
이후에는 유효한 명세·기존 단계 산출물·검증 기록을 재사용하고 결함이 생긴 단계로 회귀한다.
원요구는 고정한다. 사용자의 변경 요청은 명세 새 버전과 변경 이유로 기록한다.

## 종료 조건

`--target`이 있으면 그 값을, 없으면 9.5를 `TARGET`으로 확정한다.
TARGET은 0.0~10.0 범위의 숫자, MAX_ROUNDS는 양의 정수(기본 5),
선택 MAX_SECONDS는 양의 정수다. 잘못된 값은 실행 전 BLOCK이다.

| 조건 | 판정 | 결과 |
|---|---|---|
| BLOCK | 모순·불가능·권한 밖 요구, 해소되지 않은 중대 차단 | 사유와 남은 작업 보고 |
| 시간 한도 | MAX_SECONDS가 있고 경과시간이 이상 | 시작 전/단계 사이 확인, 새 작업을 시작하지 않음 |
| 성공 | `hard_pass AND score >= TARGET` | 증거와 최종 산출물 확정 |
| 회차 cap | N = MAX_ROUNDS이며 미달 | 검증 상태와 잔여 gap 보고 |
| plateau | 3회 이상에서 최근 2회 연속 미해결 필수 기준 수가 줄지 않고 점수 개선도 0.2 미만 | 정체 이유와 대안 보고 |

hard_pass는 모든 필수 기준의 증거 있는 pass, 전체 결과 기록, 산출물/명세 해시 일치,
중대 blocker 없음이다. 품질 점수가 높아도 hard_pass가 거짓이면 성공이 아니다.
시간/예산 제한은 완료 기준을 낮추지 않는다. 실행 중 호출을 호스트가 중단할 수 없다면
강제 취소를 보장하지 말고 반환 후 한도 초과를 기록하며 후속 작업을 중단한다.

## 회차 절차

1. 원요구·명세 해시·회차·남은 예산/시간을 확인하고 `<loop round N>`을 기록한다.
2. fresh 구현 컨텍스트에 원요구 + 명세 + 기존 단계 증거 + gap + resume_stage를 전달한다.
   첫 회차의 시작은 understand. 이전 컨텍스트의 자기변론 대신 산출물과 근거를 전달한다.
3. 분리된 검수자는 산출물·원요구·명세·실행 로그를 읽어 `shared/verification.md` 보고를 만든다.
4. `shared/evidence.py judge` 결과와 실제 검수로 종료 조건을 평가한다.
5. `<loop verdict N: hard_pass=... score=... resume_stage=...>`를 기록한다.
6. 미달이면 아래 가장 앞선 관련 단계로 회귀한다. 재사용할 증거가 없으면 더 앞 단계로 돌아간다.

| 원인 | resume_stage | 재수행 |
|---|---|---|
| 요구 해석·미결정 질문 | understand | 가정을 기록한 명세 새 버전으로 정렬(회차 중간에 사용자에게 묻지 않음) |
| 설계·인터페이스 결함 | plan | 관련 설계와 후속 구현·검수 |
| 버그·문장·레이아웃 결함 | implement | 해당 산출물 수정과 관련 기준 검증 |
| 검증 로그 누락·변경된 산출물 | review | 최신 산출물 검증, 결함 발견 시 추가 회귀 |

가정으로 대체할 수 없는 blocking_question이 남으면 그 질문에 의존하지 않는 기준까지 끝낸 뒤 BLOCK으로
종료하고 종료 보고에 그 질문을 담는다.
같은 필수 기준이 2회 연속 실패하면 단순 재시도보다 원인을 재분류한다.
직전 점수를 높이기 위해 기준을 삭제하거나 평가 방법을 완화하지 않는다.
기존에 성공한 외부 쓰기는 재조회한다. 응답 유실을 실패로 단정해 재전송하지 않는다.

## 회차 기록과 재개

회차별 명세 해시, 산출물/증거 경로·해시, criterion별 상태, 점수, review_mode,
시작·종료 시각, resume_stage, 미해결 gap과 중단 이유를 보존한다.
연결 작업 시스템이 정본이면 기존 Execution/Work Log/Graph run에 연결하고,
그 밖에는 작업별 로컬 디렉터리에 기록한다(`shared/contract.md`).
새 세션에서 최신 기록을 읽고 파일과 명세가 같은지 검증한 후 재개한다.
숫자 최고점만 보고 이전 회차를 복원하지 않는다. 최종 산출물의 검증 상태를 명확히 보고한다.
