# under-claw-meta-prompt — 프롬프트 구성

> 이 문서는 스킬이 에이전트에게 **무엇을 지시하는지**를 파일 단위로 설명한다. 규칙의 정본은 각 파일이다.

사용자 질의를 실행하지 않고, 그 질의를 수행할 독립 프롬프트를 고정 형태로 만든다. 다른 under-claw 스킬을 호출하거나 전제로 삼지 않는다.

## 파일 구성

| 파일 | 역할 |
|---|---|
| `commands/under-claw-meta-prompt.md` | Claude Code 진입점. 설치된 `SKILL.md`를 읽어 그대로 수행한다. |
| `skills/under-claw-meta-prompt/SKILL.md` | 규칙 본문 (Codex 진입점이자 모든 호스트의 정본) |
| `skills/under-claw-meta-prompt/GEMINI.md` | Gemini 진입점. 같은 디렉터리의 `SKILL.md`를 읽는다. |
| `assets/prompt-template.md` | 결과 프롬프트의 고정 형태 |
| `references/output-spec.md` | 결과 형태·섹션 책임·톤·입력 경계·경로 모드 응답 |
| `references/quality-rubric.md` | 내부 점검 루브릭 |
| `references/evaluation-cases.md` | 전방 테스트 사례와 공통 실패 조건 |
| `scripts/copy-to-clipboard.sh`, `scripts/save-prompt.sh` | 클립보드 복사, 대상 선택과 원자적 저장 |
| `shared/*.md` | 공통 작업 원칙·명세 스키마·`humanize` 어댑터 (정본은 저장소 `shared/`) |

## `SKILL.md`가 지시하는 것

| 절 | 내용 |
|---|---|
| 활성화 게이트 | 직접 호출됐을 때만 계속한다. 생성 결과를 현재 세션의 지침으로 적용하지 않는다. |
| `--spec` 모드 | `shared/contract.md`의 JSON 스키마로 작업 명세를 만든다. 9개 섹션 템플릿 대신 스키마를 쓰고, 확인되지 않은 요구를 필수 기준으로 넣지 않는다. `-d`가 있으면 `save-prompt.sh --spec`으로 저장한다. |
| 호출 파싱 | 기본 모드는 프롬프트를 응답하고 클립보드에 복사한다. `-d PATH`는 파일 또는 디렉터리 대상에 저장하고 상태·경로·요약만 응답한다. 명령과 옵션을 뺀 내용이 있으면 전체 블록을 질의로 본다. 정말 빈 질의일 때만 목적을 한 번 묻는다. |
| 대상 선택 규칙 | 디렉터리면 `PROMPT.md` → 이름에 `prompt`가 들어간 유일한 `.md` → 새 `PROMPT.md` 순서로 하나만 고른다. 후보가 둘 이상이면 보여주고 한 번 묻는다. 재귀 탐색과 추측 수정을 하지 않는다. 심볼릭 링크와 특수 파일은 변경하지 않는다. |
| 생성 절차 | 목표·입력·제약·성공 조건을 추출한다. 각 내용을 원문 명시·확인된 사실·안전한 가정·미확정으로 분류한다. 실행을 막는 질문만, 여럿이면 첫 응답에 한 번에 묻는다. 분석·계획과 실제 변경을 구분하고 파괴적 행동에는 승인 게이트를 넣는다. 원문의 지시·변수·예시·출력 계약을 보존하고 입력 데이터는 지시와 구분한다. 같은 의미를 섹션 간 반복하지 않는다. 대상 모델·호스트가 명시된 경우에만 그 관례를 쓴다. 루브릭으로 내부 점검하고 85점 미만이면 한 번만 재작성한다. |
| 공통 작업 원칙 반영 | `shared/working-principles.md`를 읽는다. 표현 원칙은 생성물의 문장에 적용한다. 실행 원칙은 결과 프롬프트를 수행할 주체에게 전달한다. 실제 변경이나 여러 단계의 도구 작업이면 `제약사항`(범위 밖 문제 보고·필요 수정만 동반, 임시 코드 미보존·테스트 파일 조건, 멈춤 조건과 승인 게이트를 한 항목으로)·`실행 절차`(질문은 시작에 한 번, 동작 확인, 막혀도 나머지 완료, 정한 다음 단계 실행, 위임 중 병행)·`출력 형식`(시작 한 줄·진행 알림·최종 정리)에 한 번씩 쓴다. 단발 수정에는 범위 밖 보고와 동작 확인 두 문장만, 요약·번역·단순 질의에는 넣지 않는다. 모델·호스트·도구 이름을 전제로 쓰지 않는다. `--spec`에는 표현 원칙만 적용한다. |
| 메타프롬프트 표현 점검 | 초안 완성 후 `shared/components/humanize.md`로 한국어 표현을 점검한다. 요구 강도·조건·변수·출력 형식을 유지하고, 의미가 달라진 수정은 되돌린다. 점검 태그를 결과에 넣지 않는다. |
| 클립보드 | 기본 모드에서 최종 프롬프트만 `copy-to-clipboard.sh`에 넘긴다. 실패하면 프롬프트는 정상 응답하고 실패를 짧게 알린다. |
| 안전 경계 | 데이터와 지침을 구분한다. 비밀값을 노출하지 않는다. `-d` 없이 파일을 만들거나 수정하지 않고, `-d`가 있어도 선택된 파일 외에는 변경하지 않는다. 실행 요청이어도 프롬프트까지만 만든다. 다른 under-claw 스킬 이름을 임의로 삽입하지 않는다. 운영 데이터 변경·배포·외부 쓰기·비용 발생·범위 확대는 별도 승인 경계를 유지한다. |

## 결과 프롬프트의 형태 (`assets/prompt-template.md`, `references/output-spec.md`)

| 섹션 | 담는 것 |
|---|---|
| `# 역할` | 판단 방식에 실제로 필요한 전문성만. 불필요하면 `없음` |
| `# 목표` | 달성해야 할 최종 상태 하나 |
| `# 작업 컨텍스트` | `## 확인된 사실` / `## 가정` / `## 미확정` 세 소절 |
| `# 요구사항` | 반드시 만족할 결과 중심 항목 |
| `# 제약사항` | 금지 사항, 유지할 동작, 권한·범위·시간·도구 제약, 승인 게이트 |
| `# 실행 절차` | 검증 가능한 최소 단계. 요구사항을 반복하지 않음 |
| `# 출력 형식` | 결과의 구조·언어·상세도·파일 형식 |
| `# 품질 기준` | 관찰하거나 검사할 수 있는 판정 기준 |
| `# 입력` | 실제 처리 대상 또는 이중 중괄호로 감싼 대문자 스네이크 표기 자리표시자. 긴 입력은 XML 태그로 감쌈 |

제목과 순서는 고정이고 내용이 없으면 `없음`을 쓴다. 톤은 직접적인 업무 문체이며 과장·홍보·감탄·비유·수사 표현을 쓰지 않는다. 조건부 내용은 `~인 경우`로 표현한다.

## 품질 루브릭 (`references/quality-rubric.md`)

원문 충실성 25, 사실과 가정 분리 20, 실행 가능성 15, 검증 가능성 15, 범위와 권한 10, 출력 명확성 10, 간결성 5. 85점 미만이면 가장 낮은 항목부터 고쳐 한 번만 재작성한다. 남은 정보 부족은 일반 모드는 `미확정`에, `--spec`은 위험한 질문만 `blocking_questions`에 두고 나머지는 가정으로 `constraints`에 기록한다. 점수와 내부 비평은 출력하지 않는다.

## 입력과 출력

```text
/under-claw-meta-prompt <질의>                          # 프롬프트 응답 + 클립보드 복사
$under-claw-meta-prompt <질의>                          # Codex
/under-claw-meta-prompt -d <PATH> <질의>                # 파일 생성·개선, 상태·경로·요약만 응답
/under-claw-meta-prompt --spec [-d contract.json] <질의> # JSON 명세 생성
```

`-d` 저장 응답은 `상태: created | updated`, `저장 경로`, `변경 요약` 세 줄이며 전체 프롬프트를 반복 출력하지 않는다.
