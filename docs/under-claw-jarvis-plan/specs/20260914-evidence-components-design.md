# 공통 명세·증거 검증·외부 구성요소

> v0.2.0 설계 이력. 외부 구성 범위는 v0.2.1에서 변경됐다. 현재는 im-not-ai를
> meta-prompt에, Ouroboros를 plan·loop에만 포함하며 제품별 어댑터 두 개는 제외한다.
> 아래 네 프로젝트 관련 내용은 당시 설계 기록이다.

## 요구와 성공 기준

기존 under-claw 3종의 호출 방식을 유지하면서 공통 명세, 증거 기반 완료 판정,
결함별 재수행, 네 외부 프로젝트의 선택 구성을 추가한다. 새 공개 스킬은 만들지 않는다.
- 높은 점수로 필수 기준 실패·누락을 상쇄할 수 없다.
- 변경된 명세/산출물과 누락된 증거는 기존 PASS를 무효화한다.
- 첫 회차 이후에는 기존 단계 근거를 확인하고 필요한 단계부터 수행한다.
- 기존 프롬프트 출력은 유지하고 --spec만 JSON 명세를 생성한다.
- 각 호스트에 설치된 세 스킬은 공통 파일을 자체 번들로 가진다.
- 외부 원본은 명시 옵션으로 고정 SHA에서 캐시하고 설치 스크립트·인증을 실행하지 않는다.

## 채택 접근과 변경 범위

`shared/`에 명세·검증·어댑터·검증기를 정본으로 두고 `tools/sync-shared.py`로
각 `skills/*/shared/`에 패키징한다. 설치된 독립 스킬이 저장소 바깥 파일을 참조하지 않는다.
entrypoint는 필요한 모듈만 읽는다. 기존 commands, SKILL.md, GEMINI.md를 같은 의미로 갱신한다.

검증기는 실제 테스트 실행기가 아니다. 파일 해시와 보고 일관성, 필수 기준 상태,
차원별 점수 범위를 확인하고 JSON 판정을 반환한다. 실제 실행/의미 검수는 agent의 책임이다.

Ouroboros 런타임을 중첩하지 않고 명세와 단계별 검증 원리를 사용한다.
im-not-ai는 의미 보존 윤문, OpenDesign은 디자인 규약·시각 검수,
Google Workspace CLI는 목적별 서비스 작업과 변경 후 재조회를 담당하는 어댑터다.

## 기록과 외부 계약

기존 작업 시스템이 있으면 해당 Execution/Work Log/Graph run을 정본으로 쓰고 증거만 연결한다.
없는 환경은 작업별 로컬 기록을 사용한다. 새로운 상태 DB나 자동 서비스 등록은 추가하지 않는다.
외부 소스 캐시는 `~/.under-claw/components`이며 기존 Claude 외부 스킬 설치와 분리된다.

## 리스크와 한계

- LLM 의미 판정의 진실성·독립성은 파일 해시만으로 증명되지 않는다.
- 부분 재수행은 앞 단계 증거가 유효할 때만 가능하며 영향받는 기준은 다시 확인한다.
- 외부 도구가 없으면 내장 방법론만 쓸 수 있다. 서비스 변경 완료로 오인시키지 않는다.
- --with-components 중간 실패 시 이전에 성공한 캐시는 남는다. 실패한 대상은 기존 사본을
  보존하며 설치 전체는 실패 코드로 종료한다. 각 교체 전 백업을 남긴다.
- 실제 장치 재배포는 이번 저장소 변경과 분리해 수행한다.

## 검증

`tests/test_evidence.py`: 통과 경계, 필수 누락, 해시 변경, 정체 원인별 복귀 정보,
경로 이탈, 수치 검증, 명세 저장·실패 시 보존.
`tests/test_components.py`: 로컬 Git 원본을 이용한 고정 SHA 설치, 백업, fetch 실패 보존,
원본 install 미실행, 독립 번들의 검증기 실행.
기존 shell 테스트와 지침 검증, shared 동기화 검사도 실행한다.
